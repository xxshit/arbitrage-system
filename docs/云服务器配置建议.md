# 云服务器配置建议

更新时间：2026-07-28

## 当前实测基础

- 技术栈：Python 3.12、Flask、Gunicorn、MySQL 8.4、Docker Compose。
- 后台任务：现多期空与期多期空5秒行情、资金费历史、价格历史、指数成分、公告、日报、充提网络、思路盯盘以及SOON/ZAMA快速基差检查等约10个常驻线程。
- 当前MySQL实际占用约 `239 MB`；最大表 `futures_price_history` 约118万行，数据与索引合计约 `198 MB`。
- 价格历史逻辑只保留最近8天，资金费只保留最近30天；InnoDB删除旧记录后文件空间不一定立即归还操作系统，因此磁盘仍需保留增长和备份余量。

## 建议配置

### 当前可用的最低配置

- `2 vCPU / 4 GB RAM / 80 GB SSD / 5 Mbps`。
- 适合：只有本人使用、维持当前币种规模和采集频率、应用与MySQL放在同一台机器。
- 风险：日报回补、全市场多交易所刷新和MySQL整理同时发生时余量较小，不适合作为长期最终配置。

### 推荐正式配置

- `4 vCPU / 8 GB RAM / 100-160 GB SSD / 5-10 Mbps`。
- 这是当前项目最合适的起步档：MySQL可获得稳定缓存，Python后台采集与网页请求互不明显争抢，并为增加盯盘币种、公告解析、爆仓数据和历史K线留出余量。
- 操作系统使用64位 Ubuntu LTS；应用与MySQL先同机部署，保持Gunicorn单worker、4线程，避免每个worker重复启动一套后台采集线程。

### 需要升级到更高配置的条件

- 同时在线用户明显增加，或新增WebSocket/逐笔成交/全深度盘口：升级到 `8 vCPU / 16 GB RAM`。
- MySQL超过约20-30 GB、历史保留期显著拉长，或大量回测与实时采集同时运行：将MySQL拆到独立数据库，再把采集器与网页服务分离。

## 部署约束

- 服务器地域优先选择能稳定访问 Binance、Bybit、OKX、Gate、Bitget 与 Lark API 的区域，并在购买前实际测试这些端点；地理距离不是唯一标准，稳定性比标称带宽更重要。
- 不直接把MySQL的3306端口暴露到公网；网站前面使用Nginx/Caddy和HTTPS，只开放80/443及受限SSH。
- 每天自动备份MySQL，并把备份复制到服务器之外；仅有云盘快照不等于完整数据库备份。
- 为Docker容器设置重启策略、健康检查、日志轮转和磁盘告警；磁盘使用率达到70%即提醒。
