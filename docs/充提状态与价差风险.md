# 充提状态与价差风险

## 2026-10-18 用户需求与证据边界

- 用户假设：某交易所某链关闭充值或提现，可能阻碍跨所资产流动并造成价格脱钩；要求在报警币种中显示充提信息。该假设不等于每个大价差均已证明由充提导致；还需区分不同资产、指数/流动性和下架等原因。
- 当前展示按“交易所＋币种＋链”陈述公开开关，不写“公链已停机”或“已确认脱钩”。全链开放也不构成可套利或无风险保证。
- 报警是历史事件，充提是最近一次采集的当前快照，两者不得混为报警当时的状态；暂不新增历史充提回放表。

## 展示

- 报警右侧最近值/24H范围下面集中显示一次“当前充提”，覆盖该币种24小时所有报警路径涉及的交易所，不在每条时间线重复。受限优先，已知正常其次，过期与未接入最后；每链完整显示名称及“充开/关/未知、提开/关/未知”，提现延迟单独标注。
- 只把明确关闭标红、明确开放标绿；未知/延迟用琥珀色。受限提示“价差需复核”，不是自动交易信号。币安、Bybit、OKX尚未接入的账户只读数据明确为未知，不假造链名、未上架或关闭结论。
- 采集时间使用明确的UTC标记；过期时显示原采集日期，并把当前两端状态降级为未知，旧值只在悬停标题中注明“上次快照”。保留完整链名，窄屏换行，链多时面板独立可滚动；没有恢复用户已删除的逐条“详细说明”。
- 现多期空原充提提示同步改为三态，过期不再保持绿色；点按、悬停、键盘焦点/Enter可看逐链状态，Escape关闭。

## 来源、缓存与刷新

- Gate公开`GET /api/v4/spot/currencies`读取`chains[].deposit_disabled/withdraw_disabled/withdraw_delayed`。使用逐链字段，不把已弃用的币级字段套给所有链；不再把带下划线的不同币种代码截断。
- Bitget公开`GET /api/v2/spot/public/coins`须返回成功码`00000`及有效列表，读取`rechargeable/withdrawable`；币级`transfer`是另一字段，不用它覆盖链充值/提现。
- 布尔值与字符串`true/false/1/0`严格解析，缺失/未识别值保留null，不补造开放或关闭。原`transfer_network_snapshot`表/JSON存储复用，无表结构改动，不新增私有API或密钥。
- 页面请求只批量读MySQL，不向交易所发请求。报警摘要新增每币一次`transfer_statuses`；明细事件不重复携带。现多期空只为当前页补充状态，且独立于行情缓存键重新判定时效，行情不更新时也不能永远保留“新鲜”充提状态。
- 后台继续按原`transfer_network_sync`运行规则同步（核验时900秒），不是5秒实时。超过两轮间隔（最低300秒）或时间向未来偏移超过60秒，标记stale；无数据/损坏/未接入标记unknown。
- 别名只使用已确认的交易所/市场作用域和倍率映射，不为充提匹配直接猜测剥掉`1000`前缀。

## Bitget旧快照诊断与修复

- 11:30:10 UTC只读核对发现Bitget全部2980条快照仍停在2026-08-04，Gate已更新至当日11:20:04，但公共任务仍显示成功。当前Bitget公开列表可读且返回5515币种。
- 只读比较发现旧记录`RBIIB/USDT`、新源`rBIIB/USDT`。旧查询会在MySQL不区分大小写的唯一键下找到旧行，但Python字典键却大小写不同，随后误走插入导致整批回滚；异常被吞后仍报任务成功。
- 新解析统一币种代码大小写，旧行按大写索引匹配并更新，不删除或重建旧记录；两所独立提交，失败保留旧快照并把任务记为错误，不再吞掉异常伪报成功。
- 同时保留每条快照的原采集时间，单所失败不阻塞另一所更新。发布后须实际验证Bitget新时间、代码唯一性及任务状态，不能仅凭单元测试宣称源同步已恢复。
