# 全站时间显示规范

## 2026-10-20：统一北京时间

用户要求所有页面统一北京时间，重点检查报警中心和历史记录；测试后直接部署，不推公开仓库。

### 边界

- 人读时间固定为 `Asia/Shanghai`（北京时间，UTC+8），不随浏览器、电脑或服务器时区变化。页头更新时间、报警时间列、资费变化历史和价差历史图明确注明“北京时间”。
- 普通 MySQL DATETIME 继续存朴素 UTC，epoch 秒／毫秒仍表示同一个绝对时刻。服务器 `TZ=UTC`、时序排序、24H 报警窗口、5秒／15秒刷新、资费滚动累计、提醒去重及真实结算时间不改。
- 前端显示已经格式化的北京时间字符串时不得再解析为本地时间或加8小时。epoch 使用显式 `timeZone: 'Asia/Shanghai'`；午夜显示00点而不是24点。
- 不批量改写数据库、不补造历史、不新增推送、不操作任何交易账号或API权限。

### 修复覆盖

- 报警：明细、最近／首次报警、峰值时间、基差追踪／打开记录和脱钩证据。
- 资费异动：发现时间和实际结算时间均从原始 epoch 显示北京，保持两者含义独立；下次结算沿用上一轮的北京时间。
- 历史图：开差／基差的横轴、采样摘要、鼠标／键盘提示和已有历史起止时间全部统一；只转换标签，不移动采样点。
- 行情：机会看板、现多／期多／美股、上游成功时间、充提弹窗、趋势快照／榜单更新时间。
- 记录：账号／设备／邀请码／安全通知／运行规则、交易对别名、趋势验证交易与K线、盯盘／推送记录。原本正确的聊天、仓位、公告、链上和实际资费明细保持不重复转换。

### 历史例外

- `TrendHorizonValidation` 和 `TrendHorizonEvent` 的立案／复核／到期／事件时间原代码明确写入朴素北京时间，继续原样显示，不误认UTC。
- `THOUGHT_WATCH_SEED` 的少量预置开始时间是北京时间字面量，网页新建／恢复及停止时间是UTC。`thought_watch_datetime` 只在原币种＋精确原始预置时间相同时按北京解释，其他值按UTC；不改旧数据。盯盘时长与历史价格取样边界也使用相同绝对时刻，避免显示和统计相差8小时。
- 日历日期／批次键／缓存版本／内部状态ISO字段不是人读时间，不作字符串批量替换；资费日期筛选仍沿用北京时间自然日、累计值仍是滚动窗口。
