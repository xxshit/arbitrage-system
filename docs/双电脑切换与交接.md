# 双电脑切换与交接

## 唯一事实来源

- 代码和长期知识文档：GitHub 的 `master` 分支。
- 实时行情、账号、聊天、报警和验证运行数据：云端 MySQL。
- 每台电脑的 `.env`、SSH 私钥、云端连接配置和聊天解密密钥：仅保存在本机受保护目录，不进入 Git。
- `docs/当前工作交接.md`：告诉新的 Codex 会话“现在做到哪里、云端运行什么版本、下一步是什么”，不保存任何密码或密钥。

不同 Codex 账号之间不会自动共享完整聊天历史，因此 Git 中的知识库与交接文档是两台电脑恢复共同上下文的正式入口。

## 开始工作

只允许一台电脑处于主要开发状态。`start_workstation.ps1` 不是一台全新电脑的安装程序；它只能在该电脑完成一次性基础配置后使用。

### 新电脑首次配置

1. 安装 Git、Python 与 MySQL/MariaDB，并下载项目代码、安装 Python 依赖。
2. 创建本机空的 `arbitrage_hub` 数据库和项目数据库用户。
3. 在项目根目录配置只属于该电脑的 `.env` 与 `cloud-backup.local.json`。
4. 安装具有云端备份只读下载能力的 SSH 私钥，并确认本机 MySQL 服务已经启动。
5. 上述私密文件和密钥不能通过 GitHub 传递；应使用用户认可的安全方式单独配置。

首次配置完成后，以及以后每次换电脑开始工作前，在项目根目录运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_workstation.ps1
```

该脚本会执行以下保护动作：

1. 工作区不干净时拒绝覆盖，防止上一台电脑的未提交内容丢失。
2. 从 `origin/master` 做仅快进更新；若本机存在未上传提交则停止并提示。
3. 触发云端 MySQL 一致性备份，下载并校验数据库与聊天密钥。
4. 先备份当前本地 MySQL，再以云端备份覆盖本地数据库。
5. 保留回退文件，数据库和密钥始终不进入 Git。

如果本次只需要查看或编辑代码，不希望覆盖本地数据库，可增加 `-SkipDatabase`。

因此，“换电脑只执行一条命令”适用于已经完成上述首次配置的电脑；全新电脑缺少数据库、私密配置或 SSH 密钥时，脚本会安全停止，不会猜测或生成替代凭据。

进入 Codex 后先说明：读取 `AGENTS.md`、`docs/README.md` 和 `docs/当前工作交接.md`，再继续项目。

## 结束工作与换机

1. 更新对应知识文档和 `docs/当前工作交接.md`。
2. 运行与改动风险相称的测试。
3. 只提交本次任务相关文件，确认 `.env`、密钥、备份和本地配置均未进入暂存区。
4. 推送 `master` 到 GitHub；如代码影响云端，再完成部署与接口验证。
5. 触发一次云端数据库备份并拉回当前电脑。
6. 另一台电脑只能在以上步骤完成后执行“开始工作”。

不要让两台电脑同时直接修改 `master`。确需并行时分别使用功能分支，合并完成前不得把任何一台的数据库反向覆盖到云端。

## 冲突与恢复

- `git pull --ff-only` 失败：停止同步，不要重置或强行覆盖；先检查两台电脑各自未推送的提交。
- 数据库同步失败：本地旧库备份保存在 `backups/local-mysql/`；云端下载副本保存在 `backups/cloud-mysql/`。
- 聊天无法解密：检查与 SQL 备份匹配的 `backups/cloud-secrets/chat-encryption.key`，不要生成新密钥覆盖旧密钥。
- 云服务器被清除：先从 GitHub恢复代码，再恢复 MySQL 备份和匹配的聊天密钥，最后补回服务器私密环境配置。

## 安全边界

GitHub 不保存 MySQL 数据、数据库备份、`.env`、Webhook、账号密码、SSH 私钥或聊天密钥。数据库同步方向默认只能是“云端生产库到本地副本”；本地库不得自动反向覆盖云端。
