# 吸筹与放量监控

## 使用与边界

入口为「实时机会 → 吸筹与放量」，提醒同时进入报警中心、全站 TIPS 和现有网页声音。管理员可以添加最多 20 个共享标签币；标签独立保存，移除不删除报警历史。如果移除的币仍入选自动候选，会继续监控该候选。所有已登录用户可查看，写入需要管理员权限与 CSRF 校验。

第一版覆盖币安当前可交易的 USDT 现货。大盘是价格与流动性初筛，不是全市场逐笔资金流；不宣称覆盖其他交易所、期货、所有链或真实投资者身份。最多 12 个自动核验币和 20 个手动标签共用一个公开分钟线连接，合计不超过 32 个币。

系统每分钟从已完成成交核验的重点池中选最多 3 个「观察候选」。它是当前规则下的观察优先级，不是收益概率、投资建议或全市场最佳币种排名。少于 3 个通过门槛就少显示，数据过期立即撤下候选。用户仍可手动添加自己关心的币。自动初筛每 10 分钟轮换，既有手动标签优先保留。

## 数据依据

- 大盘复用现有币安 `ticker/24hr` 与 `ticker/bookTicker` 缓存，不增加全市场逐币 REST 轮询。24 小时滚动成交额只用于流动性筛查，不用相邻差值伪造五分钟成交量。
- 重点池通过 `@kline_1m` 接收实时分钟汇总，按官方 `x=true` 只提交已收盘分钟；通过 `q` 与 `Q` 读取成交额和主动买入成交额。未收盘消息只确认连接新鲜度。
- 每币保留最多 90 根已收盘分钟线。当前 5 分钟成交额对比其之前完整 60 分钟的成交额除以 12。窗口不能重叠，必须连续，不补造缺失分钟。
- 主动卖出额＝总成交额－主动买入额；主动买卖差额＝主动买入额－主动卖出额。这个差额不是资金净流入，不能识别主力或证明链上持仓增加。
- 普通钱包转账不参与本模块。链上持仓、交易所地址归属、DEX 实际交换、桥接、内部归集、解锁与新闻均没有在本版核验，界面明确说明。

官方字段说明：[币安现货分钟线流](https://raw.githubusercontent.com/binance/binance-spot-api-docs/master/web-socket-streams.md)、[币安现货 REST](https://raw.githubusercontent.com/binance/binance-spot-api-docs/master/rest-api.md)。

## 判定规则：spot-flow-v1

所有短量信号先要求当前 5 分钟成交额至少 100,000 USDT，基准五分钟至少 10,000 USDT。

| 类型 | 额外门槛 |
| --- | --- |
| 放量 | 当前五分钟 / 前六十分钟折算的五分钟基准 ≥ 2.5 倍；买盘或卖盘都可触发 |
| 疑似吸筹 · 主动买盘占优 | 放量成立，主动买入占比 ≥ 60%，5 分钟中至少 3 分钟买卖差额为正；五分钟涨跌 −0.5% 至 2.5%，振幅 ≤ 5%，距窗口最高价回撤 ≤ 2%；24H 成交额 ≥ 1,000 万 USDT，盘口价差 ≤ 20 bps 且盘口新鲜 |
| 观察候选 | 放量倍数 ≥ 1.5，主动买入占比 ≥ 58%，至少 3 分钟买盘占优；五分钟涨跌 −0.5% 至 4%，十五分钟涨跌 −2% 至 10%，回撤 ≤ 2%；同样通过流动性与新鲜盘口门槛 |

候选分数由放量（最高 30）、主动买入占比（最高 30）、买盘持续分钟数（最高 20）、涨跌与回撤结构（最高 20）组成。该启发式规则没有历史胜率校准，不称为预测模型。每条事件保存当时的完整数值、窗口起止、基准、阈值、来源和风险解释，之后刷新不会覆盖旧证据。

候选最多缓存 15 秒；实时流超过 10 秒未更新即暂停候选和新提醒。盘口超过 20 秒、24H 统计超过 45 秒不能用于候选和吸筹判断。分钟线缺口暂停全部新判断并安排有界补齐。历史初始化本身不补发旧报警，须收到当前的实时收盘消息。

同币提醒至少间隔 10 分钟，仅在首次触发、类型变化、或放量倍数较前次至少再增加 50% 时新建事件。事件与去重状态同一事务提交；写入失败可重试，重启不机械重放旧提醒。活跃 TIPS 保留最多 120 秒，永久证据通过独立历史分页读取，不把全量历史装入内存。

## 资源约束与既有功能

| 项目 | 设计上限或频率 |
| --- | --- |
| 大盘缓存 | 最多 2,000 个品种，每币最多 17 个一分钟价格样本 |
| 重点池 | 手动 20 + 自动 12，去重后最多 32 |
| 行情连接 | 一个合并订阅 WebSocket，帧上限 64 KiB，接收队列上限 8；不保存逐笔成交 |
| 分钟线 | 每币最多 90 根，共最多 2,880 根 |
| REST | 每轮最多一个；每轮 5 秒，目录每小时一次、必要时补齐分钟线；失败每币至少等 60 秒 |
| 目录大小 | 只取 TRADING/SPOT，`showPermissionSets=false` 省略无用权限矩阵；保持原 16 MiB 响应保护 |
| 前端 | 当前栏目每 5 秒读取；离开后停止该页明细读取，后台及全站报警继续 |
| 报警历史 | 每页 30 条，报警中心可见时约 15 秒读取；不清理历史 |
| 保护 | 磁盘不足 512 MiB 时只暂停新监控，既有行情和报警不变 |

新增两条受原 WorkerRuntime 管理的后台任务，正常任务总数由 30 变成 32。SQL 连接在网络等待前归还。每分钟只记公共聚合健康计数，不输出标签内容、账户或原始消息。实盘开关、现多期空/期多期空 5 秒规则、已有报警筛选/静音/声音、停盯盘状态与交易权限不变；不新增外部消息推送。

新增表为 `market_flow_tag`、`market_flow_event`、`market_flow_state`。已有 54 张表保留，发布后共 57 张；回退只恢复本次网站文件，绝不回滚业务数据库或删除新事件。

## 2026-11-17 效率与边界复查

全站报警每 5 秒读取时，原实现会重复查询活跃事件、遍历整个大盘。现在由单个采集任务发布已提交事件快照；启动时加载一次，新事件提交后才更新，读取只检查有效期与当前监控范围。快照最多 32 条、120 秒，到期及时移除；历史仍从数据库分页读取。提交后快照加载失败会继续重试，不重复插入事件，也不把未提交事件发给用户。

同一份上游缓存按原单调时钟版本识别，避免时钟转换微差让旧数据重复解析。只有盘口更新时，在锁内更新模块自有标量行，读者持有的旧证据副本保持不变；分钟连续性检查不再先构造整份证据。网络补数前释放旧行情 JSON 引用，正常对象释放无需强制 GC。

同时修复三类可见问题：读取时重新检查盘口、24H统计、实时流和已收盘窗口的年龄，过期候选及时撤下；单币补齐或目录暂时失败只阻止缺证据的判断，其他有效币继续采集和报警；页面刷新保留用户展开的证据详情。目录超过两小时仍须停止判断，数据库提交失败仍须阻止新提醒，不放宽数据门槛。
