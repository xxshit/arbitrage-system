## 链上机会最新快照（2026-09-06）

- `onchain_opportunity_snapshot`：保存 BSC、Solana、Base、Ethereum 最新链上候选。唯一键为 `network + token_address`，主池地址、DEX、代币/报价币、价格、多周期涨跌、流动性、成交额、1H 买卖笔数、市值/FDV、建池时间、机会分、风险标签和来源时间都在同一行。
- 这张表只保存当前索引，不承担不可变历史回放；某条链完成新一轮解析后原子替换该链旧行，接口失败时不删除旧快照。
- 表与 `latest_market_snapshot`、`latest_dual_futures_snapshot`、`thought_watch` 和 `lark_push_state` 均无自动联动，避免链上现货候选越权进入合约盯盘或推送。

目标：交易系统里的数据不能混在一起。实时行情、历史行情、资费、报警、日报、思路复盘、交易所元数据都要按功能分表，方便查询、维护、备份和以后迁移云服务器。

## 1. 实时行情快照表

这类表只保存“最新状态”，页面排序、分页、筛选都优先读这些表，不要因为用户点击页面就重新请求交易所。

| 表名 | 功能 |

## 2. 历史行情与资费表

这类表用于趋势灯、涨跌幅、详情弹窗、日报趋势和历史资费统计。

| 表名 | 功能 |
| --- | --- |
| `futures_price_history` | Binance 合约价格历史采样 |
| `dual_futures_price_history` | BY/OK/BN 合约价格历史采样 |
| `funding_rate_record` | Binance 历史资金费率，滚动保留31天，给最近30天累计留出边界缓冲 |
| `exchange_funding_rate_record` | Bybit、OKX 已结算历史资金费率，按“交易所 + 币种 + 结算时间”去重，滚动保留31天缓冲 |

规则：历史资费是固定事实，写入后优先复用；超过保留周期再清理，避免 MySQL 越来越大。期多期空的历史净资费必须同时读到多端与空端的真实结算记录，缺少任何一端时显示待同步，不能把单边数据冒充净收益。

## 3. 报警与基差打开表

这类表用于报警中心、全局 TIPS、基差打开次数、最大值和误报警复查。

| 表名 | 功能 |
| --- | --- |
| `alert_event` | 报警事件，包括开差、基差、速变等 |
| `basis_tracking` | 基差第一次打开、方向、最近最大值、最大值时间 |
| `basis_expansion_log` | 基差每扩大 0.2% 的打开记录 |

规则：旧报警的极值扩张门槛只作为历史规则保留。2026-10-19新异动按完整有向路径和每次冲击去重，保留有符号位移，回落后重新达到0.20个百分点即另记，不要求超过上一峰值；持续高位或恒定负基差不靠绝对水平重复触发。基差追踪独立保存扩张日志，不再额外生成重复报警。

## 4. 交易所低频元数据表

这类数据通常不频繁变化，拉到后存 MySQL，以后页面直接读库。

| 表名 | 功能 |
| --- | --- |
| `index_component_snapshot` | BN/BY/OK 合约指数成分 |
| `transfer_network_snapshot` | 现货交易所充提链与充提状态 |

## 5. 日报、趋势与推送状态表

## 7. 账号安全与聊天表

| 表名 | 功能 |
| --- | --- |
| `user_account` | 账号、不可逆密码哈希、权限角色、账号等级、登录会话摘要、最近登录 IP及近似归属地、最近密码更新时间；新注册默认 `lv1`，普通账号可为 `lv1/lv2`，管理员固定 `lv3` |
| `account_security_event` | 管理员密码重置、封禁、账号名、等级和设备解绑审计，只记操作者、目标、方式与时间，不记任何密码 |
| `account_device` | 每账号的电脑端/手机端加密设备公钥、SHA-256摘要、短指纹、客户端说明、最近登录 IP及近似归属地、该槽位有效会话摘要；`user_id + device_kind` 唯一 |
| `login_security_alert` | 密码正确但设备公钥不匹配时的管理员报告，保存目标账号、设备类型、尝试指纹、客户端说明、已校验来源 IP及近似归属地、发生时间和已读时间 |

| 表名 | 功能 |
| --- | --- |
| `chat_message` | 账号之间的一对一消息；正文以AES-256-GCM密文保存，发送者、接收者、引用消息ID、撤回人、撤回时间和发送时间保留为查询元数据 |
| `chat_attachment` | 图片消息的附件元数据与AES-256-GCM加密二进制；独立于文字表并通过登录鉴权接口解密读取 |
| `chat_view_state` | 每个账号自己的清空游标和已读游标 |
| `chat_message_preference` | 每个账号对单条消息的个人删除、个人置顶状态；同一消息双方状态互不影响 |
| `chat_push_subscription` | 每个账号、每台设备的 Web Push 订阅密文；endpoint 摘要用于全局唯一去重，成功时间与失败次数用于投递健康维护 |

规则：个人点击清空时不得立即删除 `chat_message`，只推进该账号自己的 `cleared_through_id`；单条删除同样只写入 `chat_message_preference.hidden_at`。发送者执行撤回时，`chat_message.recalled_at` 成为双方共享事实，同时清空正文密文并删除附件，双方仅保留撤回提示。全局留存上限为 7 天，超过后物理删除双方原始消息、附件及对应个人偏好；图片跟随 MySQL 一起备份和恢复。

账号表 `user_account.chat_nav_hidden` 只保存当前账号是否隐藏左侧“协作记录”入口。该偏好按账号隔离，管理员修改自己的状态不会改变其他账号；它不是聊天内容，也不写入 `runtime_rule` 全局规则表。

聊天表的`encryption_version`用于区分历史明文与当前密文并保证迁移幂等。加密密钥只能保存在项目外的私密密钥文件或私密环境配置中，不能进入MySQL、Git、文档或日志；拥有完整服务器root权限并取得该密钥的人仍可解密，这不是端到端加密。

Web Push 订阅的 endpoint、`p256dh` 和 `auth` 合并后使用同一聊天 AES-256-GCM 密钥加密；MySQL 只额外保存 endpoint 的 SHA-256 摘要，不保存可直接请求的明文地址。账号停用、密码重置、本设备退出或 Push 服务确认订阅失效时删除对应记录。数据库备份与聊天密钥必须成对恢复，否则订阅密文不可解密；VAPID 私钥独立保存在云端私密配置中，不进入数据库备份。

登录 IP 字段使用 `VARCHAR(45)`，兼容规范化后的 IPv4 与 IPv6。历史行允许为空，功能上线后按真实成功登录或真实拦截事件逐步补齐；不做猜测回填。IP 可能因 NAT、VPN、移动网络或 IPv6 前缀变化而改变，只作为安全审计元数据，不属于设备身份密钥。

IP归属地字段使用`VARCHAR(160)`，保存查询当时的近似网络归属摘要，不保存外部服务原始响应或伪精确经纬度。归属地可以在管理员查看历史IP时惰性补齐，但不会覆盖对应IP本身；IP变化后必须随新IP重新查询。

密码安全规则：数据库只能保存安全哈希，不能保存可还原或可查看的明文密码。忘记密码通过管理员重置解决；重置会使目标账号已有会话立即失效，并留下不含密码内容的审计事件。设备私钥不写入数据库，MySQL 中的公钥只能验证签名，不能伪造浏览器私钥。账号等级变更同样清除会话并审计，但保留历史设备绑定，便于重新降级后继续保护。

## 趋势验证K线缓存

记录时间：2026-07-21

新增表：`trade_validation_candle`

用途：专门服务“趋势验证”页面，不再每次画图时临时从交易所拉一大段K线，也不再用通用价格快照模拟K线。

字段规划：

- `symbol`：币种，例如 `ACE/USDT`。
- `interval`：K线周期，当前固定为 `5m`。
- `bucket_at`：该根K线开始时间戳，按5分钟对齐。
- `open/high/low/close`：真实OHLC价格。
- `volume`：成交量。
- `quote_volume`：USDT成交额。
- `captured_at`：写入时间。

唯一键：`symbol + interval + bucket_at`，避免重复写入同一根K线。

缓存规则：

- MySQL保留最近7天趋势验证K线。
- 页面默认显示最近3天K线，方便横向滑动查看昨天和更早的买入/卖出点。
- 每次刷新先检查库里的最新K线；如果中间没有缺口，只向交易所补最新缺失K线；已有K线直接从MySQL读取。
- 前端刷新时保留旧图和横向滚动位置，新数据回来后再替换，避免页面先空白。

## 2026-10-21：现多期空平差与盘口历史

不新增 MySQL 表。现有 `instance/spread-history/YYYY-MM-DD.sqlite3` 的 `history` 表增加 `metric=close`（与开差相同的分钟首末极值结构）和 `metric=book`（每5分钟首份真实双腿BBO，按小时压缩）。二者按 symbol、现货交易所、指标、小时隔离；book 内含两腿报价/数量/时间，不含账户余额或凭据，不得交给普通曲线解码器。15天日分片与小时检查点沿用，磁盘不足1GiB停止新写入而非挤占业务库，待写缓存有上界。具体格式见 `opportunity_history.py` 和[分级说明](我的套利思维分级.md)。
