# 新电脑与新账户接手提示

在另一台电脑安装 Codex、克隆本仓库并打开项目后，将下面整段作为第一条消息发送；无论继续使用原Codex账户还是更换账户，都按这个入口恢复上下文：

> 这是 ArbiScope 套利系统项目的账户交接。请先完整读取根目录 `AGENTS.md`、`docs/README.md`、`docs/当前工作交接.md`，以及与当前任务有关的分类文档；核对 Git 工作区、GitHub `master` 和云端 MySQL 实时状态。以云端 MySQL 为运行事实，以 GitHub `master` 为代码和长期知识文档事实。严格区分用户假设、Codex 观点、验证结果和被推翻思路，不得把未经验证的行情判断写成固定知识。不得读取、展示或提交 `.env`、密码、Webhook、SSH 私钥、数据库凭据、聊天密钥和备份内容。完成上下文恢复后，先简短报告 Git 基线、云端服务状态、活动/停止盯盘币种、主要自动任务最近执行情况和发现的异常；不要擅自部署、重启服务或覆盖数据库，等待我提出下一项需求。

## 接手确认

新账户开始修改前，应确认：

1. 当前分支为 `master`，工作区干净，并已与 `origin/master` 同步。
2. 已读取项目规则、知识库索引和当前交接文档。
3. 已从云端 MySQL 只读核对实时盯盘与自动任务状态，没有用旧文档代替运行事实。
4. GitHub访问和云端维护权限分别由用户授权；没有从仓库或聊天获取任何秘密材料。
5. 当前账户停止并行修改后，新账户才开始写代码、推送或部署。

## 新电脑首次准备

1. 安装Git、Python 3.11+和Codex桌面应用；只有需要恢复本地数据库副本时才必须安装MySQL/MariaDB。
2. 使用有仓库权限的GitHub账户克隆 `git@github.com:xxshit/arbitrage-system.git`，不要从旧电脑直接复制整个工作目录。
3. 在仓库根目录创建 `.venv` 并安装 `requirements.txt`。首次基础配置完成后，以后切换电脑可运行 `scripts/start_workstation.ps1`。
4. `.env`、云端连接配置和SSH私钥只能通过密码管理器、加密U盘等可信渠道单独放到新电脑；不要经GitHub、聊天、邮件正文或普通网盘传递。
5. 只查看和修改代码时可暂不配置数据库与部署私钥；需要云端只读核对、同步本地数据库或部署时，再分别配置对应权限。

## 安全边界

- GitHub只传递代码和知识文档，不传递运行数据库、账号密码或任何密钥。
- 如果新账户只需要分析和改代码，可以先不配置云端部署私钥；需要部署时再由用户通过可信的账户外方式单独授权。
- 即使两个账户或两台电脑都由同一用户管理，也不得主动打开仓库中被忽略的私密配置；只在用户明确授权的运维动作中由现有脚本使用，且不得输出其内容。
