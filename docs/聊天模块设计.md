# 聊天模块设计

记录时间：2026-08-01（2026-08-02 完成可用性加固）

## 目标

在 ArbiScope 登录账号之间提供一对一聊天，并满足“任意一方清空自己的聊天记录，不影响对方”的要求。聊天数据独立分表，不能与账号、行情、报警或盯盘表混用。

## 数据表

| 表名 | 作用 |
| --- | --- |
| `chat_message` | 保存发送者、接收者、消息正文和发送时间。消息是双方共享的原始事实。 |
| `chat_view_state` | 保存每个账号针对每个联系人的可见游标、已读游标。清空只更新当前账号自己的游标。 |

## 独立清空语义

1. 甲和乙之间的原始消息仍保存在 `chat_message`。
2. 甲点击“清空我的记录”后，只把甲对应乙的 `cleared_through_id` 更新到当前最后一条消息。
3. 甲再次打开会话时，只读取该游标之后的新消息。
4. 乙的 `chat_view_state` 不发生改变，因此乙仍能看到原历史。
5. 清空后双方发送的新消息对甲、乙都正常显示。

这不是物理删除，也不是端到端加密。拥有数据库管理权限的人仍可维护数据库；网页普通账号只能读取自己参与的会话。

## 接口与前端

- 联系人接口返回其他有效账号、最近消息、在线提示和未读数。
- 消息接口只能读取当前账号与目标账号之间的双向消息。
- 发送和清空操作必须携带当前登录会话的 CSRF 校验值。
- 单条消息最多 2000 个字符，前端渲染前进行 HTML 转义。
- 页面每 3 秒增量读取新消息，不整体刷新聊天页面。
- 联系人轮询结果没有变化时不重建联系人 DOM，避免列表闪动和滚动位置复位。
- 联系人支持按账号名搜索；离线账号显示最近在线时间。
- 初次进入读取最近 100 条，继续向上按 100 条分页读取历史，且任何历史页都不能越过当前账号自己的清空游标。
- Enter 发送，Shift + Enter 换行；窄屏时联系人列表移到会话上方。
- 输入区显示字数和发送状态；用户向上阅读历史时，新消息不会强制把页面拉回底部。
- 左侧入口固定在主索引最底部，对外名称使用较低调的“协作记录”；功能内部仍保持一对一消息的安全边界。
- `user_account.chat_nav_hidden` 保存每个账号自己的入口隐藏偏好，不使用浏览器临时缓存，也不会影响其他账号。
- “运行规则”向全部账号展示当前账号的隐藏状态，只有管理员可以修改；入口隐藏后仍可从该规则卡片打开协作记录，避免失去访问路径。
- 页面标题下不展示一对一留言功能说明，左侧未读状态统一显示 `NEW`，不暴露具体未读数量；进入页面后仍可查看联系人自己的未读数。
- 联系人未读总数相较上一轮增加时复用全局报警声音播放一次；顶部处于静音时不播放，首屏已有旧未读不会因刷新页面反复响铃。

## 已验证场景

- 甲发送一条消息后，甲乙双方均能读取。
- 甲清空自己的记录后，甲读取为 0 条，乙仍能读取原来的 1 条。
- 101 条可见历史按“最近 100 条 + 更早 1 条”正确分页，并且更早读取不会穿过清空游标。
- 以上双方隔离、历史分页、账号级入口隐藏与低调未读标识场景已加入自动化回归测试；当前完整测试共 17 项通过。

## 后续可扩展

- 图片和文件消息需要独立对象存储与访问鉴权，不能把大文件直接写入消息表。
- 如需真正撤回，应设计“双方撤回”事件并明确时间限制，不能复用个人清空。
- 如需管理员公告，应单独建立广播会话或公告表，不能伪装成普通私聊。
