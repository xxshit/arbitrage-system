# 账号与邀请码管理

## 权限边界

- `admin`：可以查看“账号管理”索引、生成邀请码、查看邀请码使用记录、账号等级、账号活动时间和最近登录 IP。
- `viewer`：只能查看业务页面；服务端不会渲染“账号管理”入口，访问管理接口会返回 `403`。
- 邀请码和账号数据保存在 MySQL，页面只通过管理员鉴权后的接口读取。

## 一次性邀请码

1. 管理员在左侧进入“账号管理”，点击“生成邀请码”。
2. 新邀请码默认 7 天有效，只能成功注册一个账号。
3. 注册时通过条件更新原子占用邀请码；并发提交同一个邀请码时，只允许一个请求成功。
4. 注册成功后，系统记录使用账号和使用时间，并清除数据库中的完整邀请码，只保留哈希与前缀用于核对。
5. 未使用且未过期的新邀请码会在管理员页面显示完整值并支持复制。
6. 升级前创建的历史邀请码只保存了哈希，无法逆向恢复完整内容；页面会标明“历史邀请码仅保留前缀”，需要时重新生成。

## 账号等级

- 页面统一显示 `LV1 / LV2 / LV3`，不再显示“高等级/低等级”。鼠标或触屏辅助说明分别是“可用基本功能”“可用大部分功能”“最高权限”。
- `LV1`：新注册账号默认等级，启用一台电脑和一台手机的加密设备保护。
- `LV2`：普通账号可用大部分现有查看功能，不校验电脑/手机绑定，可在不同设备自由切换；新登录仍替换上一次会话，不能多人长期同时在线。
- `LV3`：只属于管理员，拥有全部管理权限。管理员固定为 LV3，不能降级；普通账号不能被设置为 LV3。
- 本次升级只迁移既有旧等级：管理员变为 LV3，现有另一个普通账号变为 LV2。以后通过邀请码注册的账号保持 LV1，不能被后续启动重复升级。
- 等级变更会立即使目标账号当前会话失效并写入安全审计，账号需要按新等级重新登录。

## LV1 账号的加密设备绑定

- LV1 账号分别保留一个电脑端槽位和一个手机端槽位，两端可以同时在线；同一槽位只允许一份有效会话。
- 浏览器或主屏 Web App 首次使用时在 IndexedDB 生成 ECDSA P-256 设备密钥。私钥设置为不可导出且只留在当前浏览器资料中，MySQL 只保存公钥、短指纹和会话摘要。
- 登录必须同时通过密码和随机挑战签名。某类设备已经绑定后，其他设备即使密码正确也会被拒绝，原设备会话不受影响；管理员会在左侧“安全通知”看到被拦截设备的短指纹、类型、客户端说明、来源 IP 和时间。
- 管理员可以在账号信息下查看电脑端、手机端绑定并单独解除。解除后旧设备会话立即失效，该槽位下一次登录可重新绑定。
- 每次成功登录会更新账号的最近登录 IP；LV1 账号还会分别更新电脑端、手机端槽位的最近 IP。旧记录在功能上线前没有 IP，必须等待该账号下一次真实登录后补齐，不能用文档或其他历史值推测。
- 陌生设备被拒绝并完成报告落库后，系统会向所有已启用 Web Push 的有效管理员订阅异步投递“账号、设备类型、来源 IP”安全提醒。未授权系统通知的管理员仍可在网页“安全通知”中查看，不保证获得操作系统声音。
- 封禁账号、重置密码或调整账号等级会让当前会话失效。LV1 的设备绑定不会因升级为 LV2 自动删除；以后重新降为 LV1 时继续使用原绑定设备，管理员也可以手工解除后重新绑定。

这里的“设备指纹”是当前浏览器/PWA持有的加密身份，不是硬件序列号。换浏览器、清除网站数据或重装主屏网页会丢失本地私钥，需要管理员核实本人后解除旧绑定再重新绑定。首次绑定本身必须在可信设备上完成；它不能证明正在操作电脑的人一定是账号本人，也不能替代密码保管和系统账号保护。

来源 IP 只用于账号安全审计，不是永久设备唯一标识。共享网络、移动网络、VPN、运营商 NAT 和 IPv6 切换都可能改变 IP；设备准入仍以浏览器/PWA 的 P-256 私钥为准。

## 正式短域名

当前 `sslip.io` 地址是无需购买域名即可启用 HTTPS 的临时公网地址，因此会包含服务器 IP 和独立端口。若要使用类似 `arbi.example.com` 的短网址，需要准备一个自有域名并完成 DNS 解析；随后在 Nginx 和证书配置中替换域名即可，网站和 MySQL 数据无需迁移。
