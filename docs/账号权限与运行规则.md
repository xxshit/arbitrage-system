# 账号权限与运行规则

## 账号体系

- 账号、密码哈希、权限角色、账号等级、启用状态、设备公钥和当前有效会话摘要全部保存在 MySQL，并按功能独立分表。
- 数据库永远不保存明文密码；使用 Werkzeug 安全密码哈希验证。
- 忘记密码时由管理员在“账号管理”中重置：可以设置指定新密码，也可以生成一次性显示的高强度临时密码。系统不能查看或还原旧密码。
- 重置成功后立即清除该账号的有效会话摘要，使旧设备退出；`password_changed_at` 保存最近更新时间，`account_security_event` 保存操作者、目标账号、事件类型和时间，但不保存新旧密码。
- 临时密码只通过本次 HTTPS 响应向管理员显示，响应禁止缓存；管理员应立即安全地交给账号本人，页面刷新后不再展示。
- 系统只有 `admin` 与 `viewer` 两类角色。管理员可以修改运行时间规则、生成邀请码；普通账号只能查看规则。
- 权限角色与账号等级分离。账号等级分为 `restricted`（低等级，设备保护）和 `unrestricted`（高等级，自由切换）；新注册账号默认低等级，只有管理员可以调整。
- 普通账号必须使用管理员生成的一次性邀请码注册。邀请码只保存 SHA-256 摘要，明文只在生成时显示一次，默认 7 天过期。
- 低等级账号允许一台电脑端和一台手机端同时在线；每类设备只绑定一个浏览器/PWA加密身份，并只保留该槽位的一份有效会话。
- 低等级登录除密码外还必须完成 ECDSA P-256 随机挑战签名。密码正确但设备公钥与已绑定槽位不一致时拒绝登录、保留原设备会话，并在管理员“安全通知”生成报告；错误密码不生成设备报告。
- 高等级账号不做设备绑定校验，可从不同电脑或手机使用密码登录；每次新登录替换上一份会话，不允许多台设备同时长期在线，也不为正常切换生成安全通知。
- 管理员修改账号等级时清除目标账号当前会话摘要和 Push 订阅，并写入 `account_security_event`；已有低等级设备指纹保留但在高等级期间不参与登录判断。
- 设备私钥不可导出并留在浏览器 IndexedDB，服务端只保存公钥和短指纹。这里的设备身份不是硬件序列号；换浏览器、清除网站数据或重装主屏网页后，必须由管理员核实本人并解除旧绑定。
- 管理员解除某个设备槽位时，那个设备的有效会话立即失效；封禁账号或重置密码会清除电脑、手机两个槽位的会话摘要，但保留设备绑定。
- 管理员执行账号名变更时必须清空该账号及其设备槽位的有效会话摘要并写入安全事件，只修改登录名，不修改密码、设备绑定、消息归属或联系人备注；账号本人使用新账号名、原密码和原绑定设备重新登录。
- 管理员可以在“账号管理”中封禁或解除封禁普通账号。封禁会立即清空有效会话，使已登录设备在下一次请求时退出，并拒绝后续登录；解封不会恢复旧会话，账号需重新登录。封禁与解封均写入安全事件，当前管理员不能封禁自己。
- 会话 Cookie 使用 `HttpOnly + SameSite=Strict`；管理员写操作额外校验会话内 CSRF Token。

## 五根 30MIN 扫描链路

- 全市场启动阶段扫描不再绑定每日 08:00。
- 默认每 `1800 秒` 执行一次，并与半小时时间槽对齐。
- 只读取已经收盘的 30MIN K线，当前未收盘K线会被排除。
- 扫描 Binance USDT 永续候选，读取 30MIN K线、持仓历史和全市场多空账户人数比。
- 最近五根按“第一根开盘到第五根收盘”的整体涨幅计算，不机械相加每根涨幅。
- 强启动要求：五根整体涨幅至少 40%、CVD 上涨、持仓上涨、人数比下降。
- 启动前蓄势要求价格尚未明显启动，但持仓、人数比、CVD和量能先行形成结构。
- 强启动币第一次出现时只做一次性机会提醒，不自动加入“思路分析”盯盘；持续盯盘必须由用户明确选择。
- 当 Binance 数据完全不可用时，本轮必须标记失败并保留失败原因，不能用“0个信号”伪装执行成功。

## 5MIN 急涨扫描链路

- 默认每 `10 秒` 读取一次本地 MySQL 价格桶，单根5MIN默认阈值为 `15%`；两项均在“运行规则”展示，管理员可以调整，普通账号只读。
- 本地初筛达到阈值附近后才向 Binance 复核候选币，不对全市场逐币发送高频K线请求。
- 盘中5MIN需连续两次确认，已收盘5MIN直接确认；同一行情段按点火、加速、极端扩张分阶段去重。
- 该链路只产生一次性机会提醒，不擅自把币加入持续盯盘名单；持续盯盘仍由用户明确选择。

## 每日 08:00 的职责

- 日报 08:00 只做趋势榜汇总和 Lark 前三名推送。
- 上下架公告仍按每日时间规则独立运行。
- 最近执行、最近成功和最近失败时间覆盖保存在 `automation_status`，不重复累积无意义状态记录。

## 运行规则页面

左侧“运行规则”集中展示实时行情、页面读取、走势盯盘、趋势筛选、每日任务、历史补充、静态资料、报警阈值和数据保留规则。

页面下方另设“同币异名配对”管理区：

- 全部登录账号都能查看已生效的标准币名、另一名称、适用交易所、市场类型、倍率和确认依据。
- 只有管理员可以新增或删除手工记录；新增、删除接口同时要求登录会话和 CSRF 校验。
- `PLAY = PLAYSOUT`、`SKYAI = SKYAI1` 与倍率合约 `XEC = 1000XEC` 是内置核验记录，网页只读，避免误删后再次漏配。
- 手工保存后立即清除现多期空、期多期空的旧行情缓存；下一轮刷新会按新别名归一化。
- 手工录入代表管理员确认，不代表系统仅凭名称自动验证；确认依据应填写官网、合约地址或交易所公告等可复核信息。

“界面显示”属于账号级交互设置，固定放在所有运行、阈值和数据保留规则之后，作为页面最后一组；管理员与普通账号看到的分组顺序保持一致。

管理员修改可编辑时间后，后台线程在下一轮读取 MySQL 新值，无需改 HTML 或重新写代码。知识阈值与数据保留规则当前只读，避免随手修改造成策略口径漂移。
