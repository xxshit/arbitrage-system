# 账号权限与运行规则

## 账号体系

- 账号、密码哈希、角色、启用状态、当前有效会话摘要全部保存在 MySQL，并按功能独立分表。
- 数据库永远不保存明文密码；使用 Werkzeug 安全密码哈希验证。
- 系统只有 `admin` 与 `viewer` 两类角色。管理员可以修改运行时间规则、生成邀请码；普通账号只能查看规则。
- 普通账号必须使用管理员生成的一次性邀请码注册。邀请码只保存 SHA-256 摘要，明文只在生成时显示一次，默认 7 天过期。
- 同一账号只有一个有效会话。新设备登录会替换会话摘要，旧设备的下一次请求立即返回登录失效。
- 会话 Cookie 使用 `HttpOnly + SameSite=Strict`；管理员写操作额外校验会话内 CSRF Token。

## 五根 30MIN 扫描链路

- 全市场启动阶段扫描不再绑定每日 08:00。
- 默认每 `1800 秒` 执行一次，并与半小时时间槽对齐。
- 只读取已经收盘的 30MIN K线，当前未收盘K线会被排除。
- 扫描 Binance USDT 永续候选，读取 30MIN K线、持仓历史和全市场多空账户人数比。
- 最近五根按“第一根开盘到第五根收盘”的整体涨幅计算，不机械相加每根涨幅。
- 强启动要求：五根整体涨幅至少 50%、CVD 上涨、持仓上涨、人数比下降。
- 启动前蓄势要求价格尚未明显启动，但持仓、人数比、CVD和量能先行形成结构。
- 强启动币第一次出现时自动加入“思路分析”盯盘；用户手动停止过的旧币不会被扫描器强行重新开启。
- 当 Binance 数据完全不可用时，本轮必须标记失败并保留失败原因，不能用“0个信号”伪装执行成功。

## 每日 08:00 的职责

- 日报 08:00 只做趋势榜汇总和 Lark 前三名推送。
- 上下架公告仍按每日时间规则独立运行。
- 最近执行、最近成功和最近失败时间覆盖保存在 `automation_status`，不重复累积无意义状态记录。

## 运行规则页面

左侧“运行规则”集中展示实时行情、页面读取、走势盯盘、趋势筛选、每日任务、历史补充、静态资料、报警阈值和数据保留规则。

管理员修改可编辑时间后，后台线程在下一轮读取 MySQL 新值，无需改 HTML 或重新写代码。知识阈值与数据保留规则当前只读，避免随手修改造成策略口径漂移。
